# KYC Verification

ZB ID provides a central KYC module that other ZB services call to validate national IDs against the e-Gov registry, run FCB credit bureau searches, and screen individuals and organisations against World-Check AML watchlists. Every verification is persisted as an auditable record. {{ className: 'lead' }}

<Note>
  All KYC endpoints are service-to-service. Call them with a **client credentials** Bearer token that carries the required scope for the endpoint. See [OAuth2 client credentials](/authentication#oauth2-client-credentials) for how to obtain one, and [Roles & Permissions](/roles-permissions#permissions) for the KYC scopes.
</Note>

---

## Overview {{ id: 'overview' }}

<Row>
  <Col>

    The KYC endpoints live under `/v1/kyc`. Each one requires a specific scope on the calling client's token:

    | Endpoint | Method | Scope |
    |----------|--------|-------|
    | `/v1/kyc/validate-id` | POST | `kyc:validate` |
    | `/v1/kyc/credit-check` | POST | `kyc:credit-check` |
    | `/v1/kyc/screen-individual` | POST | `kyc:screen` |
    | `/v1/kyc/screen-corporate` | POST | `kyc:screen` |
    | `/v1/kyc/screen-result` | POST | `kyc:screen` |
    | `/v1/kyc/screen-toolkit` | GET | `kyc:screen` |

    Two behaviours reduce duplicate provider calls:

    - **National ID validation is cached** for 30 days per national ID. A repeat validation within that window returns the stored record with `cacheHit: true`.
    - **Watchlist screening is deduplicated.** An individual is matched by national ID or by a normalized `fullName` plus date of birth; an organisation by its normalized name. A matching prior case is reused with `cacheHit: true` instead of opening a new one.

    Credit checks are never cached; each request calls the bureau fresh.

  </Col>
  <Col sticky>

    <Note>
      In non-production environments the upstream providers are stubbed, so these endpoints return deterministic sample data without contacting the real registries. Behaviour, request shapes, and response shapes are identical to production.
    </Note>

  </Col>
</Row>

## The verification object {{ id: 'the-verification-object' }}

<Row>
  <Col>

    Most KYC endpoints return a verification object describing the persisted record.

    <Properties>
      <Property name="id" type="string (UUID)">
        Unique identifier for this verification record.
      </Property>
      <Property name="userId" type="string (UUID) | null">
        The linked user, if one was supplied. `null` for pre-registration checks.
      </Property>
      <Property name="nationalId" type="string | null">
        The national ID for individuals, or the normalized identity key used for watchlist deduplication.
      </Property>
      <Property name="type" type="string">
        One of `EGOV`, `FCB`, or `WORLDCHECK`.
      </Property>
      <Property name="status" type="string">
        One of `PENDING`, `VERIFIED`, `REJECTED`, `COMPLETED`, or `FAILED`.
      </Property>
      <Property name="statusReason" type="string | null">
        A human-readable reason when the verification was rejected or failed.
      </Property>
      <Property name="externalRef" type="string | null">
        The provider's reference for a watchlist case, when one exists.
      </Property>
      <Property name="cacheHit" type="boolean">
        `true` when the record was served from cache or reused via deduplication rather than a fresh provider call.
      </Property>
      <Property name="requestSnapshot" type="object | null">
        The request payload sent to the provider, minus any injected credentials.
      </Property>
      <Property name="responsePayload" type="object | null">
        The provider's response, as stored.
      </Property>
      <Property name="createdAt" type="string (ISO 8601)">
        When the record was created.
      </Property>
    </Properties>

  </Col>

## Validate a national ID {{ id: 'validate-a-national-id', tag: 'POST', label: '/v1/kyc/validate-id' }}

<Row>
  <Col>

    Validate a national ID against the e-Gov registry. Requires the **kyc:validate** scope. Results are cached for 30 days per national ID. When the ID is active and the linked user is currently at KYC tier `NONE`, the user's tier is raised to `BASIC`.

    ### Request body

    <Properties>
      <Property name="nationalId" type="string">
        The national ID to validate. Up to 20 characters.
      </Property>
      <Property name="userId" type="string (UUID)">
        Optional. Link this verification to an existing user so a successful check can raise their KYC tier.
      </Property>
    </Properties>

    An active ID returns `status: "VERIFIED"`. An ID belonging to a deceased person, or one that is not active in the registry, returns `status: "REJECTED"` with a `statusReason`.

  </Col>
  <Col sticky>

    <CodeGroup title="Request" tag="POST" label="/v1/kyc/validate-id">

    ```bash {{ title: 'cURL' }}
    curl -X POST https://zbid-api.lioncapventures.com/v1/kyc/validate-id \
      -H "Authorization: Bearer eyJhbGciOiJSUzI1NiIs..." \
      -H "Content-Type: application/json" \
      -d '{
        "nationalId": "63-123456A78",
        "userId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
      }'
    ```

    ```python {{ title: 'Python' }}
    import requests

    response = requests.post(
        'https://zbid-api.lioncapventures.com/v1/kyc/validate-id',
        headers={
            'Authorization': 'Bearer eyJhbGciOiJSUzI1NiIs...',
            'Content-Type': 'application/json',
        },
        json={
            'nationalId': '63-123456A78',
            'userId': 'a1b2c3d4-e5f6-7890-abcd-ef1234567890',
        }
    )

    verification = response.json()
    ```

    ```javascript {{ title: 'Node.js' }}
    const response = await fetch(
      'https://zbid-api.lioncapventures.com/v1/kyc/validate-id',
      {
        method: 'POST',
        headers: {
          'Authorization': 'Bearer eyJhbGciOiJSUzI1NiIs...',
          'Content-Type': 'application/json',
        },
        body: JSON.stringify({
          nationalId: '63-123456A78',
          userId: 'a1b2c3d4-e5f6-7890-abcd-ef1234567890',
        }),
      }
    )

    const verification = await response.json()
    ```

## Screen an individual {{ id: 'screen-an-individual', tag: 'POST', label: '/v1/kyc/screen-individual' }}

<Row>
  <Col>

    Open a World-Check AML screening case for an individual. Requires the **kyc:screen** scope. If a case already exists for the same national ID, or the same normalized `fullName` plus date of birth, that case is reused (`cacheHit: true`).

    ### Request body

    <Properties>
      <Property name="fullName" type="string">
        The person's full name. Up to 80 characters.
      </Property>
      <Property name="dateOfBirth" type="string">
        Date of birth, `YYYY-MM-DD`.
      </Property>
      <Property name="gender" type="string">
        `MALE` or `FEMALE`.
      </Property>
      <Property name="nationality" type="string">
        ISO 3166-1 alpha-2 country code (for example, `ZW`).
      </Property>
      <Property name="nationalId" type="string">
        Optional. National ID, up to 20 characters. Improves deduplication.
      </Property>
      <Property name="userId" type="string (UUID)">
        Optional. Link the verification to an existing user.
      </Property>
    </Properties>

    A newly opened case is returned with `status: "PENDING"` while screening results are resolved.

  </Col>
